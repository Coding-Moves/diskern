# Diskern v0.3.0

Diskern v0.3.0 is a release-readiness update focused on safer scan roots,
clearer downloads, stronger release checks, and better contributor visibility.

The scanner now handles repeated, nested, missing, and unreadable roots from
the shared engine, so the CLI and desktop app report the same honest result.
The landing page also labels the selected Windows installer correctly, whether
GitHub returns the MSI or EXE asset first.

## Highlights

**Shared scan-root validation.** Missing or unreadable scan roots now fail in
`diskern-core`, which means the CLI and desktop app both show a real error
instead of a misleading empty scan.

**Repeated and nested roots count once.** Scanning a parent directory together
with one of its children no longer doubles file counts, progress bytes, or
duplicate candidates.

**Download labels match the asset.** The landing page now shows `.msi
installer` or `.exe installer` based on the Windows asset it actually links.

**Desktop action safety tightened.** Quarantine actions are checked against
the completed backend report, with stale-finding and graph-aware verdict
guards.

**Release checks are stronger.** Desktop backend tests now run in the Tauri CI
matrix, and the release checklist records the version files, CI gates, tag
process, draft review, and updater checks.

## Fixes

- Report missing or unreadable scan roots as errors from the shared engine.
- Count repeated and nested scan roots once.
- Preserve invalid-root context across operating systems.
- Keep root-anchored rules working for relative scan paths.
- Refuse excluded scan roots with a clear error.
- Correct the Windows installer label on the landing page.
- Apply the site theme to the document root to avoid white flashes and
  mismatched scrollbars.
- Include macOS Chrome cache paths in the rules database.
- Keep system `var/tmp` matching away from user and project directories.
- Use singular wording for one CLI finding or duplicate set.
- Keep site lockfile/package naming aligned.
